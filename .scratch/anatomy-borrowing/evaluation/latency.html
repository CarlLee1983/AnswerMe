快取命中率如何決定平均讀取延遲

每次讀取只走兩條路之一：命中走快路徑，花 C 毫秒；未命中走慢路徑，花 D 毫秒。平均延遲 L 就是兩條路徑依命中率 h 加權的平均。

核心說明

L = h × C + (1 − h) × D。L 對 h 是一條直線，兩端分別是 D（全部未命中）與 C（全部命中）；h 每增加 0.01，L 改變 (C − D) / 100 毫秒。

因此，只有在 C < D 時，提高命中率才會降低平均延遲；C > D 時結論反轉，C = D 時命中率完全不影響 L。在來源的初始值下，未命中只占 25% 的讀取，卻貢獻了絕大部分的平均延遲。

怎麼讀這些結果

直線的斜率是 C − D。把公式展開成 L = D + h × (C − D) 就能看出：h 從 0 走到 1，L 從 D 等速移到 C。命中率提升的效益大小，取決於兩條路徑的延遲差，而不是命中率本身的高低。

慢路徑主導平均值。當 D 遠大於 C，即使未命中比例很小，(1 − h) × D 仍占平均延遲的大部分。試著先把 C 調到 0，再改回來、把 h 從 0.75 調到 0.9：在初始值下，後者讓 L 下降得更多，因為減少未命中次數比加快命中路徑更有效。

結論何時反轉。本頁允許 C 調到大於 D。這時直線往右上升，提高命中率反而讓平均延遲變長；這在真實快取中不常見，但能說明「提高命中率一定更快」只在 C < D 時成立。

不要重複計入 C。來源指定 D 已包含未命中路徑上的全部工作，例如先查快取失敗再讀後端的時間。因此未命中的耗時是 D，不是 C + D；若你手上的量測只計後端讀取，需先把查快取的時間加進 D 再套用本模型。

L = h × C + (1 − h) × D
  = D + h × (C − D)

h：命中率，0 到 1
C：命中延遲（ms），初始 4
D：未命中延遲（ms），初始 120，已含未命中路徑全部工作
初始 h = 0.75

來源與限制

來源：公式、變數定義、初始值（h = 0.75、C = 4 ms、D = 120 ms），以及「D 已包含未命中路徑全部工作」的規定，全部取自 tests/answer-me/interactive/input/model.txt。

性質：來源說明這是示意用、確定性的雙路徑模型，不是正式環境的量測。頁面上的數字都是模型計算值，不是實測延遲。

本頁的推論與設定：斜率 C − D、反轉條件與各路徑占比，是由公式推導而來。滑桿範圍（C、D 為 0 到 200 ms）是本頁為了能展示反轉情境所選的範圍，來源沒有規定。

模型沒有涵蓋的部分：平均值不反映尾端延遲（例如 p99）；真實系統中 C、D 會隨負載波動，命中率也可能與快取大小、存取模式、逐出策略互相影響。這些都不在來源模型內。
