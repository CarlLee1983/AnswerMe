# 借鑑 humanize-writing：逐項評估

日期：2026-10-23。使用者問 answer-me 的輸出是否要套用自己開發的 `humanize-writing`（去 AI 味潤稿）。前一輪的結論是不接成固定步驟，改為逐項評估可借用的部分；本紀錄是那份評估，技能本身尚未修改。

## 來源與限制

- 來源：本機 `~/.agents/skills/humanize-writing`，commit `335a23a`（MIT，作者 CarlLee1983）。該目錄沒有 git remote，GitHub 上也查不到 `CarlLee1983/humanize-writing`，所以用本機 commit 固定範圍。
- 讀過：`SKILL.md`、`references/zh-tw.md`（32 類句式＋台灣用語對照＋自檢清單）、`references/interface-copy.md`；`en.md`、`narrative-*.md` 只看了用途。
- 兩條 ADR 劃出邊界：
  - [ADR 0001](../../docs/adr/0001-core-with-optional-production-skills.md)：外部技能只能是可選的製作能力。把潤稿寫成必經步驟會觸發它的否證條件。
  - [ADR 0004](../../docs/adr/0004-borrow-ste-without-compliance.md)：「寫清楚技術解說」一節不加句長、禁詞或符合度門檻，`scripts/check.py` 也不掃解說文字。所以借用只能寫成「修辭動作」層級的原則，不能搬字詞清單。`zh-tw.md` 本身也說「禁的是修辭動作，不是字面」，兩邊方向一致。
- 定位差異：`humanize-writing` 改的是別人的稿，目標是讓作者聽起來像自己；answer-me 是自己產出解說，沒有作者原本的語氣要保留。與「作者語氣」綁在一起的規則（第 2 優先的口頭語、第 31 條）對 answer-me 沒有作用對象。

## 逐項評估

分類：**已涵蓋**＝answer-me 已有等效或更嚴的規則；**候選**＝相容、對解說有用、目前沒涵蓋；**部分**＝只有一部分相容；**不採用**＝與 ADR 或既有功能衝突，或在解說文中很少出現。

| # | 項目 | 分類 | 理由 |
| --- | --- | --- | --- |
| 1 | 二元對比殼 | 部分 | 解說常需要糾正讀者真的會有的誤解，這時「不是 A，是 B」帶有資訊。只借「沒有資訊的翻案對比」這一半。 |
| 2 | 命令模板開頭 | 不採用 | 「先問自己一個問題」與 answer-me 刻意提供的可選預測問題（`SKILL.md`「驗證與交付」）長得一樣，借進來會互相打架。操作步驟用祈使句本來就合理。 |
| 3 | 假洞見標記 | 候選 | 解說最容易出現「本質上」「關鍵在於」接一句常識。寫成動作：刪掉標記後句子撐不住，就換成具體機制或刪掉。 |
| 4 | 提示性冒號 | 候選 | 基線有少數接近鋪梗的冒號。須連同放行清單一起借（標籤、條列引言、條件），否則會誤傷大量合法冒號。 |
| 5 | 抽象壓力語言 | 已涵蓋 | 「段首先回答子問題」已排除宏大背景開頭。 |
| 6 | 排比湊數 | 候選 | 「每一項都要有來源支撐，成立的不論幾項都留」與「保留證據」相容，可直接用在優點清單與比較表。 |
| 7 | 轉場與強調贅語 | 部分 | 填充片語（「由於……的事實」）已由「寫出動作與主體」涵蓋；「值得注意的是」併入第 3 項處理即可，不另立。 |
| 8 | 空泛收尾 | 候選 | answer-me 規定了交付內容，但沒有禁止結尾的整體評價或重複摘要。可寫成：講完最後一個有依據的結論就停。 |
| 9 | 防禦性否定堆疊 | 部分 | answer-me 要求寫出限制與「不是實測」，這類否定是證據的一部分，不能刪。可借「同一條限制只寫一處」，與第 14 項合併。 |
| 10 | 「本文」免責聲明 | 不採用 | 驗證範圍必須寫出來，換主詞是潤飾層級的事。HTML 文件用「本頁」交代範圍可以接受。 |
| 11 | 段尾固定警語 | 已涵蓋 | 「將影響判斷的證據缺口集中說明，避免在每句插入待補占位符」。 |
| 12 | 讓步轉折句型／口號小標 | 候選 | HTML 的節標題是實際交付物。「每節回答一個子問題」可以延伸成「小標講出該節的答案，不寫口號」。 |
| 13 | 分號串長句 | 已涵蓋 | 「一句集中說明一個重點」，且拆句時保留原意。 |
| 14 | 查核範圍分散在各段 | 已涵蓋 | 同第 11 項；上次 ste-zht 借用後，驗證狀態也有集中定義。 |
| 15 | 破折號 | 不採用 | 單一字元的禁令就是 ADR 0004 拒絕的機械規則；基線的命中也多是範圍符號。 |
| 16 | 疊加保留語氣 | 部分 | 「保留可能性及要求強度」已涵蓋強度不變；「多層保留詞刪到一層」沒有涵蓋，可作為一句補充。 |
| 17 | 挑戰與展望段 | 不採用 | 解說文中很少出現；真的出現時，第 8 項就能處理。 |
| 18 | 聊天殘留 | 部分 | 「好問題」「希望對你有幫助」可借。「如果需要我展開哪一部分」不能借，因為 answer-me 規定交付時要列出可追加的圖解或互動。知識截止式的模糊說法已由「保留證據」處理。 |
| 19 | 動詞名詞化 | 已涵蓋 | 「把『進行處理』換成來源可支持的具體動作」。 |
| 20 | 意義膨脹與尾巴分析 | 候選 | 解說成果審視時，容易在事實後面掛「體現了良好的設計」。可寫成：事實後面不追加來源沒說過的意義。這也接得上「區分事實與推論」。 |
| 21 | 模糊歸因 | 已涵蓋 | 關鍵主張附近要有來源；來源的模糊主張標為作者說法。 |
| 22 | 繫詞迴避 | 候選（低） | 「扮演……的角色」在架構解說中常見，但影響只到可讀性，不影響正確性。可併入第 28 項的例子。 |
| 23 | 假範圍 | 不採用 | 解說很少出現；「從註冊到付款」這類同軸範圍反而常用。 |
| 24 | 抽象名詞抒情 | 不採用 | 屬於散文問題，技術解說很少出現。 |
| 25 | 借喻包裝 | 已涵蓋 | answer-me 的實物示意要求運作方式一一對應、標明示意、指出對應不成立之處，比 humanize-writing 的三個條件更嚴。可以借一個點：比喻道具用中文原本的說法（關卡，不用「票」）。 |
| 26 | 商業與模型黑話 | 候選（低） | 解說材料（PR 描述、agent 報告）常帶黑話，但 answer-me 的規則是保留來源術語。只能借「自己的說明不新造黑話」，引述照原樣。 |
| 27 | 長短句高低差／同義詞輪替 | 部分 | 同義詞輪替已由「固定名稱」涵蓋，而且更嚴；句長節奏屬句長規則，ADR 0004 不加。 |
| 28 | 直譯腔 | 候選（高） | answer-me 常把英文原始碼、文件、PR 解說成中文，這是最容易出直譯腔的位置。「會對同事講出口嗎」的判準不是字詞清單，符合 ADR 0004；也與「保留必要英文術語」相容（翻不出好中文就留原詞）。 |
| 29 | 宣傳腔 | 不採用 | 解說文中很少出現。 |
| 30 | 假具體 | 已涵蓋 | 「不補造數字」「不要為了補齊步驟編造命令或結果」。 |
| 31 | 論壇服裝 | 不採用 | 管的是潤稿者自己加的口頭禪，answer-me 沒有這個作用對象。 |
| 32 | 排版層 | 候選 | 「散文被切成粗體標題清單」「粗體灑滿」會出現在對話與 Markdown 交付。注意 answer-me 自己的 `SKILL.md` 也大量使用粗體標題清單：那是給 agent 讀的規格，不在範圍內，只約束交付給使用者的解說。 |

| — | `narrative-*.md` | 不採用 | answer-me 規定引用或解釋創作文案時保留原文語氣。 |

## 候選彙整

依對解說品質的影響排序，供使用者選擇：

1. **直譯腔（28，併 22、25 的道具用語）**：最符合 answer-me 的實際工作，判準不是字詞清單。
2. **意義膨脹（20）**：直接保護「事實與推論分開」，成果審視最常用得到。
3. **假洞見標記（3，併 7）**＋**空泛收尾（8）**：開頭和結尾的空殼，改起來成本低。
4. **小標講內容（12）**＋**排版層（32）**＋**按鈕講動作（interface-copy §2）**：只影響 HTML／Markdown 交付物。
5. **小幅補充**：疊加保留語氣刪到一層（16）、自己不新造黑話（26）、台灣慣用語原則與「示意數據」改字。

部分項目（1、9、18）借用時需要附例外，寫進技能的字數成本較高，建議只在它們真的出現在演練成品時再處理。
