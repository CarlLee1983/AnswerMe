Answer Me把「說明一下」變成可追溯的解說。

這個專案提供一套 Codex 技能指引。Agent 依它研究來源、整理關係、選擇交付形式，並核對答案的證據與成果。核心產品是 SKILL.md 中的行為規則。

01

它要幫你理解什麼？

概念學習

建立能拿來推理的認識

對象是陌生概念、文章或系統。讀 repo 時沿一條具體流程追到負責的程式，說明資料如何流動、各步驟為何存在。

例：「這個 repo 收到請求後，如何讀資料並回傳結果？」

成果審視

看懂變更，以及證據支持到哪裡

對象是 agent 的方案、diff 或執行結果。說清前後行為與取捨，區分程式內容、測試紀錄和 agent 自己的宣告。

例：「這次 diff 改了什麼？現有測試能證明哪些行為？」

領域用語：CONTEXT.md。預設範圍是解說與關鍵證據核對；完整 code review、程式修改需要另行提出。SKILL.md，8 行

02

一次解說如何完成？

以下是技能規定的工作順序。這些步驟由 agent 執行；流程圖呈現的是指引，並非 repository 中的固定執行引擎。

Read理解目標、讀取來源

找出使用者卡在哪裡。沿實際流程研究，保留程式位置、原文或測試紀錄。

Choose確認交付格式

未指定時詢問 HTML、Markdown 或對話；等待選擇時可繼續研究與提供摘要。

Explain組織解說與成果

定義用文字；關係用圖解；操作確實有助理解時，才加入互動。

Verify核對、開啟、交付

核對主張與來源。文件要實際存在；HTML 要本機離線開啟，互動要實際操作。

格式與呈現是兩個決定

選 HTML 也可以只有文字與靜態圖解。選 Markdown 就要建立真正的 .md 檔；對話全文不能代替檔案。

製作能力可以選用

show-me、archify、visualize 可在適合且可用時協助製作。核心技能仍負責證據與最終檢查。

依據：SKILL.md，10–31、45–59、65–80 行。例外：單一事實直接簡答；使用者已指定格式時沿用。完整旁白影片不屬首版能力。

05

「檢查通過」到底代表什麼？

這個專案有幾種不同的證據。它們驗證的對象不同，不能彼此替代。

檢查能支持不能據此推定
快速檢查
python3 scripts/check.py		Skill frontmatter 合格、顯示欄位存在、指定文件的行內相對檔案連結可解析。解說語意正確、外部網址可用、使用者已理解。
瀏覽器檢查
node tests/answer-me/browser/verify.mjs		保存的互動頁通過指定數值、鍵盤、390 px 排版與離線檢查；也確認故障輸入能被辨識。目前技能重新產出的答案仍有同樣品質。
新的行為演練只提供 skill、情境與原始材料，重新生成答案，再由驗收者核對語意及實際成果。每個未演練情境都正確，或讀者一定已理解。

依據：check.py，14–69 行 · 演練說明 · verify.mjs

提交時，檢查的是哪個版本？

已安裝的 pre-commit→check.py --staged→Git index 暫存快照→同一套檢查

這樣可避免工作目錄中尚未暫存的修正，掩蓋實際待提交內容的錯誤。Hook 必須另行安裝；此處說明機制，不表示本機已啟用。

check.py，72–95 行 · docs/checks.md，21–29 行

三組演練各有目的：evidence 核對宣告與證據；interactive 驗證離線互動與修復；conditions 確保參數效果的說明保留「增加、減少、不變」三種條件。另有交付格式的對話演練。

本次任務正是此流程：研究專案 → 詢問格式 → 使用者選 HTML → 製作與驗證。

維護專案

先讀 SKILL.md 理解行為，再讀 docs/checks.md。快速檢查需要 Python 3.10+、PyYAML 與外部 skill validator。

技能行為改動後，依演練 README 重新生成並驗收；檢查器或 hook 改動時，再執行 test_checks.py。
