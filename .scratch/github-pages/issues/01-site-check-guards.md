# 01: 網站檢查防線

**What to build:** 維護者提交網站內容時，既有檢查器（含 pre-commit 的暫存快照模式）會擋下三類問題：網站檔案含 `file://` 或使用者家目錄形式的本機路徑、網站 HTML 的站內相對連結指向不存在的檔案、範例頁以標記載入外部 HTTP(S) 資源。介紹頁與範例頁以固定檔名約定區分，介紹頁只允許 Google Fonts。repo 沒有網站目錄時，既有檢查行為不變。規格見 [spec.md](../spec.md)。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [x] 合法網站樹（含介紹頁載入 Google Fonts）通過檢查。
- [x] 網站檔案含 `file:///Users/...` 或家目錄路徑時失敗，錯誤訊息指出檔案與原因。
- [x] 網站 HTML 的 `href` / `src` 相對連結指向不存在的檔案時失敗；外部網址與頁內 anchor 不受影響。
- [x] 範例頁以 `script`、`link`、`img`、`iframe` 等標記載入 HTTP(S) 資源時失敗；同一網址出現在一般超連結時通過。
- [x] 介紹頁載入 Google Fonts 以外的外部資源時失敗。
- [x] `--staged` 模式下，暫存區的錯誤不會被工作目錄的修正掩蓋，未追蹤檔案不能滿足暫存中的站內連結。
- [x] 沒有網站目錄時，既有檢查結果不變。
- [x] 以上皆由檢查器單元測試覆蓋（先寫失敗測試），既有單元測試全數通過。
- [x] 檢查說明文件補上網站檢查的範圍與限制（只做靜態掃描、不驗證語意）。
