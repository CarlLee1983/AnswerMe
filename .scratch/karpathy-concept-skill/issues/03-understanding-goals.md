# 兩種用途各要讓誰理解什麼，才算有幫助？

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 01
Part of: [把 Karpathy 的解說概念轉成可重用 skill](../map.md)

## Question

對「概念學習」與「成果審視」，第一批使用者的背景、輸入材料與卡住的地方各是什麼？一次解說後，使用者應能做出哪種觀察、預測、判斷或下一步行動？

## Discussion branches

- 用兩種用途各一個真實案例定義需求；輸入可能是概念名稱、連結、原文、程式碼、diff 或 agent 報告，哪些是首版必需？
- 既有知識、可投入時間與未知程度：哪些可從對話推斷，哪些需要先問使用者？
- 成果審視需要幫助判斷到什麼程度？如何區分解釋、核對證據與正式 code review／安全稽核？

## Resolution criteria

使用者確認兩種用途的代表案例、理解目標與任務邊界。具體驗證方式由「如何驗證解說可信，而且達到理解目標？」承接。

## Answer

使用者於本對話回覆「採用建議」，確認下列受眾、代表情境與完成目標。

- **首批受眾**：有程式開發背景，但不熟眼前主題的使用者本人；以此作為初始解說深度的基準，再依對話調整。
- **概念學習的代表情境**：閱讀陌生 repo，理解系統如何運作。以該 repo 的程式與文件為材料，協助使用者掌握主要流程與關係。
- **成果審視的代表情境**：看懂 agent 的 diff、修改理由與測試結果。
- **成果審視的完成目標**：理解變更與取捨、核對關鍵主張的證據，並能判斷下一步。完整 code review 另行處理；本技能的解說不等於已完成正式、全面的程式審查。

這些是首批代表情境；媒介、語言、時間成本與交付環境仍由[首版支援哪些媒介、語言與交付環境？](04-media-scope.md)決定。如何驗證上述目標、取得理解回饋與處理證據缺口，由[如何驗證解說可信，而且達到理解目標？](07-evidence-and-validation.md)決定。
