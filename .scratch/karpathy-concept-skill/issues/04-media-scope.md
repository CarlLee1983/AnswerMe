# 首版支援哪些媒介、語言與交付環境？

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 01, 02
Part of: [把 Karpathy 的解說概念轉成可重用 skill](../map.md)

## Question

以文字、圖解、互動 HTML 與影片為候選，首版承諾哪些形式？它們應在哪裡被閱讀或操作、容許多少等待與成本，語言和可近用性有何需求？

## Discussion branches

- 影片的交付定義：實際可播放影片、動畫圖解，還是腳本／分鏡？這些成果如何清楚區分？是否首版就需要旁白？
- 交付環境：對話內閱讀、可離線開啟的檔案，或指定平台？使用者是否需要保存、分享或匯出？
- 語言與閱讀需求：繁體中文、英文或依提問語言？是否借用 STE 的簡明原則，何時才需要嚴格標準規則？
- 可接受的製作時間、外部工具與付費依賴；如果依賴不可用，使用者希望拿到哪種替代成果？

## Resolution criteria

使用者確認首版媒介清單、各形式的交付定義、語言與環境限制，以及時間／成本偏好。媒介範圍不代表每次都必須產出全部形式。

## Answer

使用者於本對話回覆「採用建議」，確認以下四項選擇。

- **媒介範圍**：首版支援文字、圖解與互動 HTML。完整旁白影片留待後續，需要時可先提供腳本／分鏡；腳本／分鏡須以其實際形式交付，不視為已製成影片。
- **交付形式**：對話中提供重點與圖解；互動成果交付可離線開啟、保存的 HTML 檔案。這裡的離線開啟包含該成果本身的閱讀與互動，不要求使用者啟動網站服務。
- **語言與風格**：繁體中文為主，保留必要英文術語；採短句、明確用詞與具體例子，借用 STE 的簡明原則。這是文字風格選擇，不是 STE 標準符合度的承諾。
- **時間、成本與替代形式**：先交付核心解說，再依理解需要增加製作成本；可接受數分鐘的產製時間，作為偏好而非完成時間保證。新增付費服務前先確認；工具不可用時提供較簡單、但仍有用的形式。

具體的選型、升級與替代形式行為由[Skill 如何選擇解說形式，何時交回使用者決定？](05-selection-behavior.md)承接；HTML 的離線與互動驗收由[如何驗證解說可信，而且達到理解目標？](07-evidence-and-validation.md)承接。
