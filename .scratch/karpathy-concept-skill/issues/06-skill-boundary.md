# 新 skill 自己負責什麼，如何運用既有能力？

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 02, 05
Part of: [把 Karpathy 的解說概念轉成可重用 skill](../map.md)

## Question

新 skill 的核心責任與可攜性邊界是什麼？應能獨立工作、選擇性借助既有技能，還是依賴特定工具組合？需要哪些指引或資源才能支援已決定的行為？

## Discussion branches

- 對照能力研究，哪些非顯而易見的行為需要由新 skill 擁有？哪些應重用既有能力？
- 目標執行環境與技能間的介面：輸入、成果、失敗回報及能力缺席時的替代路徑如何定義？
- Skill 命名、發現描述、使用者呼叫方式與交付／安裝位置；決策前提出的候選名稱為 `answer-me`。
- 是否確有需要附上 references、scripts 或 assets？依已確認需求決定，不預先建立骨架或新增依賴。

## Options considered

以下為決策前的架構分析；最終選擇記於下方 Answer：

| 方向 | 主要取捨 |
| --- | --- |
| 自成一體 | 較容易攜帶，但可能重複既有媒介製作指引，且不能因此承諾完整影片能力。 |
| 核心可獨立工作，選擇性借助既有能力 | 可重用既有工具；須定義能力查找、輸入／輸出與缺席時行為，避免介面隨工具變動而失效。 |
| 固定路由到指定技能 | 邊界明確，但簡單解說也可能增加依賴與操作成本。 |

比較時一併考慮：若某個媒介整合失效，能否只停用該整合而維持其餘已承諾的行為？

## Resolution criteria

使用者確認技能的責任、目標環境、依賴與缺席行為、名稱和交付位置；後續作者能判斷最小必要檔案集合。這張票只做設計決策，不建立或安裝 skill。

## Answer

使用者於本對話回覆「採用建議」，確認以下責任邊界與交付規劃。

### 核心與可選能力

採用「核心可獨立工作，按需使用既有能力」。新 skill 負責理解目標、選型、解說組織、證據呈現與成果檢查；製作圖解或互動成果時，可使用 `show-me`、`archify`、`visualize` 等現有能力。

這些技能是可選依賴，並非固定必經的路由。缺席或無法交付所需成果時，依[已定案的替代與詢問規則](05-selection-behavior.md)處理。選用其他技能製作成果，不改變本技能對解說與成果檢查的責任。

核心接收使用者問題、來源材料與對話中的理解需求；選用的製作能力承接解說目標、相關材料與所需形式，將產出的成果及其限制交回核心檢查。所需形式須保留[媒介範圍決策](04-media-scope.md)的語言與交付要求。具體驗收規則由[如何驗證解說可信，而且達到理解目標？](07-evidence-and-validation.md)定義。

### 名稱、環境與來源位置

- **名稱**：`answer-me`，可明確以 `$answer-me` 呼叫；自動選用情境依既有選型決策。
- **首版目標環境**：Codex。
- **唯一原始檔位置**：本專案的 `skills/answer-me/`，即 `/Users/carl/Dev/CMG/AnswerMe/skills/answer-me/`。
- **後續安裝方式**：讓 `~/.codex/skills/answer-me` 連結至上述來源目錄，維持一份來源。本輪只記錄設計，不建立技能檔案或安裝連結。
- **最小檔案集合**：`SKILL.md` 與 Codex 顯示資訊 `agents/openai.yaml`。只有確實需要較長的媒介指引或範例時才增加參考檔；目前沒有已確認的需求要增加 scripts 或 assets。
