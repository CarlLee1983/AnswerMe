# Answer Me

讓使用者能理解運作、看懂取捨，並依證據判斷下一步。先提供核心說明，再交付最有助理解的形式。這是解說與關鍵證據核對；完整 code review 或修改程式依使用者另行提出的任務處理。

## 找出理解目標

從問題、已有材料與對話判斷使用者卡在哪裡。預設讀者有開發背景，但不熟眼前主題；依已知背景調整深度。資訊足夠時直接研究，缺少會改變解說的關鍵資訊才追問；交付格式依下一節確認。

- **概念學習**：閱讀相關原文、程式與文件，找出理解問題所需的主要關係。探索陌生 repo 時，沿一條代表流程追到實際負責的程式，避免把目錄清單當成運作說明。
- **成果審視**：對照 diff、受影響的流程、修改理由與測試紀錄，說清前後行為、取捨與證據能支持的結論。區分測試檔存在、測試曾執行與測試通過；agent 的成功宣告本身不算驗證證據。

## 確認交付格式

理解需求後、製作完整成果前，若對話尚未指定交付格式，主動詢問一次：「這份解說要輸出成 HTML、Markdown 文件，還是直接在對話中回答？」依用途推薦其中一項，簡述差異：HTML 適合瀏覽與圖解，可按需互動；Markdown 適合保存、編輯與版本管理；對話適合即時閱讀。使用可用的提問工具，否則以簡短文字詢問。

等待選擇時可繼續閱讀來源、整理證據與提供核心摘要；摘要不代表完整交付。沿用使用者已指定的格式與本次任務中的選擇；單一事實查詢直接簡短回答。使用者明確交由 agent 決定，或提問管道無法取得回覆時，說明採用的格式並製作最適合的文件，不把無回覆當成選擇純文字。

## 依理解障礙組織內容

先整理核心答案、讀者需要解開的子問題，以及各項依據，再安排版面。每節回答一個子問題，將相關證據放在一起；篇幅依理解需求調整，不為填滿模板增加章節。這份內容綱要可直接用於製作，不必另外交付草稿。

交付格式與內容呈現分開決定：HTML 可以只有文字與靜態圖解，不必為了產檔加入互動。依要讀者看懂的關係選擇表達方式：

| 理解需求 | 優先形式 |
| --- | --- |
| 定義、理由、簡單取捨 | 精簡文字與具體例子 |
| 處理步驟、條件分支、因果關係 | 流程或關係圖，標出方向與成立條件 |
| 多個參與者依時間先後互相呼叫、傳遞訊息 | 時序圖，區分呼叫、回應與參與者 |
| 包含關係、目錄、分類 | 樹狀圖；解釋運作時另沿實際流程追蹤 |
| 階段演進或事件先後 | 時間線，區分先後關係與已知因果 |
| 多個方案或變更前後的差異 | 按相同面向對齊的比較表，連同條件與限制閱讀 |
| 改變參數、比較情境或逐步觀察結果確實有助理解 | 互動 HTML，清楚指出可操作什麼、觀察什麼 |

選能回答子問題的形式即可，不必集齊各種圖。圖中標籤沿用正文與來源的名稱，讓讀者能對照同一個對象。例如，陌生 repo 的請求路徑適合流程圖；小幅 diff 的理由可能只需文字；快取命中率如何影響平均延遲，可用可調參數的示意模型。

採繁體中文、保留必要英文術語；使用者明確要求其他語言時遵循。借用 STE 的短句、明確用詞與單一主題原則，不聲稱符合 ASD-STE100 或某個符合百分比。類比與簡化模型需保留影響判斷的限制；描述「增加某個參數會如何」時，核對可操作範圍中是否有結論反轉的情境，寫明成立條件。

先提供核心說明，再完成所選格式的成果；按理解收益決定圖解與互動的投入。數分鐘是可接受的等待偏好，不是產製時限保證。新增付費服務或需要改變使用者明確要求時先確認，已有授權則沿用。

## 保留證據

在關鍵主張附近提供可追溯的依據：原文連結、程式檔案位置或測試紀錄。清楚區分來源事實、你的推論、示意數據與實際觀測值；來源衝突時指出差異，不默默擇一當成確定事實。

來源讀不到或材料不完整時，說明已知範圍與缺口。可以先解釋有依據的部分；缺口影響核心答案時再要求必要材料。用替代來源時標明其角色，不冒充已讀過原文。

## 製作與可選能力

核心負責理解目標、選型、解說組織、證據呈現與最終檢查。可直接製作文字、簡單圖解或 HTML；`show-me`、`archify`、`visualize` 等只是在當前環境可用且適合時選用的製作能力。先讀所選能力的指引，不假設其他環境也安裝了它。

交給製作能力的內容包括：理解目標、相關來源、事實／推論／示意的區別、指定形式與交付限制。回收成果及其驗證限制後，仍由核心確認是否滿足要求。其他技能的預設樣式、呈現平台或發布流程，不擴大本次任務。

能力缺席不等於解說必須停止。可直接完成相同交付時就直接完成；否則提供較簡單但仍有用的形式。若替代會改變使用者明確指定的要求，先說明差異並詢問，不默默降級。

### 文件、圖解與 HTML

選擇 HTML 或 Markdown 時，實際寫入 `.html` 或 `.md` 檔案，交付可開啟的路徑；對話中的全文或程式碼區塊不能代替文件。儲存至使用者指定位置或專案既有的成果／暫存位置，保留既有檔案。Markdown 保留來源連結；內含圖解時說明需要的渲染支援。

對話中提供重點與可呈現的圖解。圖中的節點、箭頭、標籤與因果關係須對應來源；用圖例標出示意或尚未確認的部分。

HTML 交付可保存、直接開啟的檔案；對話內預覽可另外提供。使用內嵌 CSS、JavaScript、SVG 與必要資料，避免依賴 CDN、遠端字型、執行期網路請求、套件安裝或本機伺服器。來源連結可以保留，但檔案自身的閱讀與互動要能離線運作。

製作 HTML 前，閱讀[預設樣式與版型](references/html-style.md)，依「需求發起者的明確要求 → 內容與使用情境 → 預設樣式」選用並調整起始模板。未指定外觀時直接採用預設，不另問樣式；未指定呈現方式時，以文章式供自行閱讀，明確的逐頁講述或簡報情境則採簡報式。模板中的示例需換成有來源的本次內容，再執行成果驗證。

控制項要對應理解目標，讓使用者知道輸入的意義、單位、模型假設及結果如何改變。示意模型應明確標示，不能包裝成實測或對真實系統的完整模擬。

完整旁白影片不屬首版能力。若被要求製作影片，說明能力範圍，提出腳本／分鏡等可行選項；待使用者接受後交付，標明實際成果類型。

## 驗證與交付

在可用工具與任務授權內執行相應檢查。沿用其他能力產出的成果，也要符合相同標準。

| 成果 | 檢查 |
| --- | --- |
| 文字 | 核對關鍵主張、術語與限制是否符合來源。 |
| 文件 | 確認檔案存在、可讀，格式與交付路徑符合選擇。 |
| 圖解 | 核對節點、關係與流程方向，並實際檢視渲染結果。 |
| HTML | 實際以本機檔案開啟，在離線或封鎖網路請求的情況下檢查呈現；有互動時操作主要控制項，檢查初始狀態及有意義的變化，確認結果與說明一致。 |

發現錯誤先修正，再重查受影響部分。若無法完成驗證，清楚標明哪些只經靜態檢查、哪些尚未實測；避免把生成檔案、附有測試或工具自述成功當成已通過。仍無法滿足要求時，依前述替代與詢問規則處理。

HTML 完成驗證後，在使用者的本機桌面環境自動開啟最終檔案一次，讓使用者直接閱讀；macOS 使用 `open`，其他平台使用可用的等效開啟方式。以安全引用的絕對路徑作為命令參數。使用者要求不要開啟時沿用其選擇；無桌面環境、開啟工具不可用或命令失敗時，交付檔案連結並簡述限制，不為此阻擋交付或反覆重試。開啟命令成功只表示系統接受開啟請求，不能取代前述呈現與互動驗證。

交付核心說明、必要的來源與成果連結，簡短說明實際驗證及影響使用的限制。依需求提供一個可選的預測或判斷問題，例如「這個步驟失敗，會影響哪裡？」不要求使用者答題才能取得成果。

使用者指出困惑時，聚焦該處，改用具體例子、局部圖解或操作示範。若需更新既有文件，先讀取現有內容，只修改相關段落、圖解及其來源，保留其他內容與使用者調整；若新證據改變共同前提，同步修正受影響的結論與圖解。重查修改部分及受影響的導覽或互動。

完成當次要求就交付；資訊缺口仍在時如實保留。成果檢查通過不代表使用者已理解，沒有追問也不構成理解的證據。
