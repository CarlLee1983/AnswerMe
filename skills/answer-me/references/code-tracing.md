# 跨檔追蹤與變更影響

問題跨越多個檔案或模組時使用：一條功能流程、模組間怎麼協作、架構概覽，或一次變更會波及哪裡。來源標示、驗證狀態與交付仍依 [SKILL.md](../SKILL.md)。

## 界定範圍

從問題定出**起點**與**終點**，只追連接兩者的路徑。

- **起點**：功能流程從使用者或外部觸發的入口開始，例如路由、CLI 命令、事件處理器、排程；變更影響從 diff 改到的函式、類別或常數開始。
- **終點**：流程追到回應、寫入或對外呼叫為止；變更影響追到入口、對外輸出或測試為止。
- **分支**：只展開問題問到的分支，例如使用者問扣款失敗，就追失敗路徑，其餘分支用一句話帶過並附位置。
- **停止**：抵達終點、進入第三方套件或框架內部，或剩下的呼叫與問題無關時停止，並寫出停在哪裡、為什麼停。

用 agent 既有的搜尋與閱讀工具逐跳前進，不先盤點整個 repo，也不建立 parser 或索引。目錄清單只用來找起點，不當成運作說明。

## 逐跳追蹤

每一**跳**記下呼叫處與被呼叫的定義，兩端都附檔案與行號，例如 `routes.py:7` 呼叫 → `orders/service.py:13` 定義。

- **往下找**：讀呼叫處，循 import 找到定義；同名函式或多個實作時，依型別、建構處或注入點確認實際是哪一個。
- **往上找**：用符號名搜尋引用（例如 `rg -n "compute_total\("`），逐筆打開確認是真的呼叫，排除註解、字串、同名的不同物件與測試替身。
- **間接呼叫**：事件訂閱、依賴注入、設定檔、裝飾器、框架 hook、反射或字串路由不會在呼叫處直接寫出目標。找到註冊或組裝的位置，把這一跳寫成「經 `wiring.py:9` 註冊」；找不到註冊處時，標為推論並寫出依據。
- **資料流**：說明重要的值在哪裡產生、哪一跳改變它、最後寫到哪裡或回給誰。

追蹤時發現文件說法與程式不符，例如 README 說非同步而程式是同步呼叫，把兩者並列並以程式為行為依據。

## 分清四種關係

每條關係主張標明它屬於哪一種，圖與文字使用相同分類：

| 關係 | 依據 | 常用形式 |
| --- | --- | --- |
| **結構關係**：import、包含、繼承、實作 | 宣告與 import 敘述 | 關係圖或樹狀圖 |
| **執行流程**：誰呼叫誰、先後與分支 | 呼叫處與控制流程 | 時序圖或流程圖 |
| **業務流程**：使用者或領域上的步驟，例如下單、保留庫存、扣款 | 程式行為對照文件、命名與需求 | 步驟流程，每步接回負責的程式 |
| **推論關係**：依命名、文件或慣例判斷，程式中未直接看到 | 寫出推論依據 | 圖中以虛線區分 |

結構關係不代表執行時一定會呼叫；業務步驟要接回實際負責的程式，對不到程式的步驟標為缺口。圖只畫回答子問題所需的部分，規模依[樣式指引](html-style.md)的流程或關係圖元件，超過就拆圖。

## 導覽順序

涉及多個模組時，按讀者建立理解的順序排列內容：

1. **入口**：觸發點與輸入。
2. **核心邏輯**：做出決定的函式與規則。
3. **資料存取**：讀寫的位置與資料形狀。
4. **外部依賴**：第三方服務、套件或環境。
5. **例外處理**：失敗從哪一步分岔、怎麼回到入口。

依問題刪去用不到的站，或把例外處理併入發生處。每一站寫出它在流程中的角色、交給下一站的資料與位置，讓讀者知道為什麼往下讀。

## 變更影響

從 diff 出發，分三層陳述，每層獨立標示：

1. **已確認的變更**：diff 實際改了哪些定義、條件或常數，附 diff 行號；說明哪些輸入會讓行為與變更前不同，例如只有特定條件下才分岔。
2. **靜態關係支持的潛在影響**：搜尋到的直接依賴者，以及經它們到達入口或對外輸出的路徑，每一跳附位置與深度。這些是可能受影響的範圍，寫成「可能」；與變更無關的引用（例如只用到同檔另一個常數）排除並說明理由。
3. **需要執行才能確認的影響**：列出要驗證的行為與能證明它的檢查。對照測試是否觸及變更分支：測試存在、測試曾執行、測試通過分開說；通過的測試沒走到變更分支時，該行為仍是**未驗證**。

靜態追蹤只能說明程式寫了什麼、可能影響誰，執行時的影響要有執行紀錄。agent 宣稱「其他模組不受影響」時，以第 2 層的搜尋結果核對。

## 既有的 Understand Anything 圖（可選）

定起點前，看專案根目錄有沒有 `.ua/knowledge-graph.json`（舊版為 `.understand-anything/`）。有就照下列步驟用它找起點與候選關係；沒有就照上面的流程追蹤，不安裝、不執行 Understand Anything，也不建議使用者為此產生圖。

1. 執行 `python3 <本技能目錄>/scripts/ua_graph.py --root <含 .ua 的目錄> check`。狀態為 `missing`、`invalid` 或 `incompatible` 時不用這張圖。其餘狀態下，圖在任何情況都只當線索；`stale`、`dirty` 時，列出的變更路徑與標為 `[changed since graph]`、`[missing now]` 的節點另外回原始碼重找位置；`unknown` 時無法算出變更，所有位置都視為未確認。沒有 Python 時，可直接讀 JSON 的 `version`、`project.gitCommitHash` 與要查的節點，並與 `git rev-parse HEAD` 比對。
2. 用 `find <名稱>` 找節點位置，用 `neighbors <節點 id>` 看候選關係。在原始碼中搜尋符號時排除 `.ua/` 目錄，免得圖檔的內容混進搜尋結果。
3. 每條要寫進解說的關係都回原始碼確認，引用原始碼的位置，不引用圖。圖的 `calls` 邊與摘要是分析時由 LLM 依 import 與命名推斷，沒有證據欄位，可能把間接呼叫畫成直接呼叫。
4. 圖與原始碼不符時以原始碼為準；若這個差異會誤導讀者，在解說中說明。

最終的 HTML 或文件不嵌入、也不依賴圖的檢視器。
