# A｜互動解說

[開啟互動解說](explainer.html)。直接以瀏覽器開啟本機檔案即可；三個滑桿會即時更新平均時間，按鈕可切換幾個比較情境。

模型來自 [model.txt](../input/model.txt)：**L = h × C + (1 − h) × D**。起始值 h = 75%、C = 4 ms、D = 120 ms，因此平均讀取時間是 **33 ms**（命中貢獻 3 ms，加上 miss 貢獻 30 ms）。當 C 小於 D，提高命中率會降低平均時間；若 C 大於 D，結果相反；兩者相等時，命中率不影響平均值。降低其中一條路徑的延遲，只會按該路徑的發生比例影響平均值。D 已包含完整 miss 路徑時間，不再額外加 C。此模型是示意計算，並非實際系統量測。

# B｜修復版

[開啟修復版](repaired.html)。保留原始 [existing-explainer.html](../input/existing-explainer.html)；修復版把計算程式內嵌，滑動命中率時會同時更新百分比和平均時間。原檔依賴外部 script，且靜態顯示 31 ms；按模型起始值應為 33 ms。

# 檢查

我檢查了兩份內嵌 JavaScript 的語法，並以 `file://` 在 headless Chrome 開啟解說頁，確認起始顯示 33 ms。另由獨立瀏覽器檢查在離線模式下驗證：兩頁沒有執行期錯誤或 HTTP(S) 請求；解說頁通過 10 組數值情境、4 個快捷情境、鍵盤方向鍵操作，390 px 視窗沒有水平溢出；修復頁在命中率 0%、100%、50%、75% 時分別顯示 120、4、62、33 ms。這些檢查確認指定情境的離線互動，並非完整瀏覽器相容性測試。
